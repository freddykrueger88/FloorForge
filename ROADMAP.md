# ROADMAP.md

# OpenFloorball Coach Platform

## Produktentwicklung und langfristige Planung

---

# 1. Entwicklungsphilosophie

Die Plattform wird nicht durch maximale Feature-Anzahl erfolgreich.

Sie wird erfolgreich durch:

* echten Trainernutzen
* einfache Bedienung
* technische Qualität
* Vertrauen
* offene Architektur

Jede Entwicklungsphase baut auf der vorherigen auf.

Keine Phase soll unnötige Komplexität erzeugen.

---

# 2. Entwicklungsphasen

## Phase 0 – Fundament

### Ziel

Eine stabile technische Grundlage schaffen.

---

### Aufgaben

Projektstruktur:

* Repository einrichten
* Entwicklungsumgebung definieren
* Coding Standards festlegen
* CI/CD vorbereiten
* Dokumentation erstellen

Architektur:

* Grundarchitektur implementieren
* Datenmodell definieren
* Authentifizierung vorbereiten
* API-Struktur erstellen

### Ergebnis

Eine saubere Basis für langfristige Entwicklung.

# 4. Qualitätskriterien

Eine Version gilt erst als fertig, wenn:

* Nutzerproblem gelöst
* Datenschutz geprüft
* Tests vorhanden
* Dokumentation vorhanden
* Performance akzeptabel
* Architektur sauber bleibt

---

# 5. Vermeidung von Feature-Bloat

Neue Features benötigen Antworten:

1. Welches Problem lösen wir?
2. Wer braucht es?
3. Warum ist es besser als die aktuelle Lösung?
4. Passt es zur Vision?
5. Welche Komplexität erzeugt es?

---

# 6. Langfristiges Ziel

OpenFloorball Coach soll die Referenzplattform für Floorball-Coaching werden.

Nicht durch:

* Datensammlung
* Abhängigkeit
* geschlossene Systeme

Sondern durch:

* Vertrauen
* Offenheit
* Qualität
* Community
